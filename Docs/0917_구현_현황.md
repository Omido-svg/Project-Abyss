# 공통 규칙

## 1. 전투 구조 · 부위 — ✅ 구현

### 구현

- 플레이어 4부위: 머리 / 왼팔 / 오른팔 / 다리.
- 일반 몹은 BodyPart를 만들지 않고 SingleHpTargetModel을 사용하는 단일 HP 대상.
- 부위형 대상과 단일 HP 대상을 BodyPartTargetModel / SingleHpTargetModel로 분리.
- BodyPartSkillAccessPolicy가 과거 CharacterSlotConfig의 직렬화 값보다 우선한다.
  - 머리: 평타 / 결투 / 도사림
  - 양팔: 평타 / 결투
  - 다리: 도사림
- 부위 피해 시 부위 HP와 전체 HP가 같이 내려가는 이중 차감 경로.
- 일반 부위 피해는 HP 1에서 약화로 멈추는 죽음의 저항.
- 파괴 권한이 있는 피해는 이미 약화된 부위에만 일반 파괴를 허용.
- 한 타격에서 정상→약화→파괴가 동시에 일어나지 않도록 피해 전 상태를 기준으로 전이.
- 파괴된 부위를 다시 때리면 부위 HP 대신 전체 HP 직접 피해.
- 전체 HP 0 또는 부위 전멸 양쪽 사망 경로.
- 팔 약화 굴림 감소, 다리 약화 속도 최대 감소, 머리 약화 평타 전용, 파괴 시 슬롯 상실, 머리 파괴 시 최대 빛 감소.
- Character.RestoreCurrentHP에서 전체 HP +N과 최저 비파괴 부위 +N을 동시에 적용하고 약화/파괴 상태는 그대로 유지.
- 파괴 부위→약화 재생용 별도 rulebreaker 경로 존재.

### 핵심 코드

- Assets/1. Scripts/Runtime/Characters/CharacterBase/BodyPartTargetModel.cs
- Assets/1. Scripts/Runtime/Characters/CharacterBase/SingleHpTargetModel.cs
- Assets/1. Scripts/Runtime/Characters/CharacterBase/CharacterBodyPartController.cs
- Assets/1. Scripts/Runtime/Characters/CharacterBase/Loadout/BodyPartSkillAccessPolicy.cs
- Assets/1. Scripts/Runtime/Systems/Resolution/DamageManager.cs

### 미정

- ⚠️ 다리를 조준했을 때 별도 처리.
- ⚠️ 플레이어/엘리트 절대 부위 HP 값은 정본 12장에서 다시 미정으로 명시되어 있으므로 현재 authoring 숫자를 최종값으로 보면 안 됨.

## 2. 턴 진행 — ✅ 구현

- TurnManager가 기세 초기화/이월 → 턴 시작 → 캐릭터 턴 시작 → 속도 굴림 → AI 계획 순으로 진입.
- 같은 부위에서 파생된 행동 슬롯은 같은 속도값을 공유.
- 도사림은 planning commit 계층에서 비용과 즉시 효과를 확정하고 Resolution에서 중복 실행하지 않도록 상태를 기록.
- 유진 환형도 카드 보너스는 계획 중 즉시, 무기 교체는 다음 턴로 예약.
- COMBAT 해결은 속도 내림차순.
- 속도차 1~5는 빠른 쪽 +1, 6 이상 +2.
- 일방타격에는 합 판정 전용 속도 보정을 적용하지 않음.

주요 코드:
- Systems/BattleFlow/TurnManager.cs
- Systems/Stats/SpeedManager.cs
- Systems/Planning/BattleActionPlanCommandService.cs
- Systems/Resolution/ActionPhaseSorter.cs

## 3. 합 — 굴림 소모전 — ✅ 구현

- 양쪽 굴림을 하나씩 소비하는 LoR식 합.
- 동률 재굴림.
- 한쪽 굴림이 먼저 끝나면 잔여 굴림 일방타격.
- 합 도중 주 대상 사망/종료 시 같은 행동의 남은 굴림 소멸.
- 상대의 살아 있는 공격 슬롯을 정확히 조준할 때 합 성립.
- 같은 상대 슬롯을 여러 슬롯이 노리면 마지막/최신 계획 슬롯이 합을 가져가고 나머지는 일방타격.
- 합 승자는 paired exchange의 승수 다수결, 잔여 일방타격은 합 승수에 포함하지 않음.
- 결투 vs 결투 rider gate와 일반 공격 경로 분리.
- 사용시/매칭시/승리시/패배시/합 종료시 hook 계층 존재.
- 합 종료 hook은 잔여 일방타격까지 끝난 뒤 발생.

주요 코드:
- Systems/Resolution/ClashMatchPolicy.cs
- ClashBuilder.cs
- ClashManager.cs
- ClashContinuationPolicy.cs
- Skills/Skill.cs

주의: ClashManager의 일부 과거 주석에 합 승리 위세 보너스 문구가 남아 있어도 실제 PrestigeRuleSettings.ClashWinCharge는 0이다.

# 결론

Default-Battle-Test @ a4026af는 전투 코어의 뼈대만 있는 단계는 이미 지났다.

- 부위/죽음의 저항/합/속도/기세/고조/열광/빛/위세/데미지/창/로드아웃/런 경제의 공통 시스템은 대부분 실제 런타임으로 연결되어 있다.
- 올라프와 유진은 현재 정해진 풀 구조가 거의 전부 playable하다.
- 감정 증강도 63장 roster와 열광 offer는 완성됐다.
- 큰 콘텐츠 미완은 히후미 후반 풀, 감정 52 proxy, 아이템 최종 효과, 아직 설계되지 않은 적 콘텐츠다.
- 기획 미정과 별개로 지금 바로 고칠 수 있는 확정 구현 누락은:
  1. 히후미 C +3 피해 증가
  2. 견고/무장해제
  3. 히후미 공용 도사림 2장
  이 세 가지가 확인된다.

이 문서를 이후 구현 체크리스트의 기준으로 사용하되 0917 정본 MD/XLSX가 바뀌면 정본 변경과 구현 변경을 분리해서 갱신한다.
