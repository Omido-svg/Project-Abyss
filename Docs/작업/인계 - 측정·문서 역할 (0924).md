지금까지 이 프로젝트에는 역할이 셋 있었다.

- **사용자** — 구조(메커니즘 · 조건 · 제약)를 정한다. 최종 결정권

### 현재 작업 방식

Codex 데스크톱 작업에서는 로컬 레포를 직접 읽고 고치고 검증할 수 있다. 외부에서 zip을 받아 수동으로 되돌려 넣는 절차는 기본 흐름이 아니다.

1. `Project-Abyss`와 `abyss-workspace`의 실제 파일을 먼저 읽는다
2. 작업 노트 → 정본 → 요약/스펙 → 개발로그 순으로 반영한다
3. 관련 검증 스크립트를 실제로 실행한다
4. **커밋 · 푸시는 사용자가 요청할 때만** 한다

파일이 로컬에 없거나 접근할 수 없을 때만 사용자에게 파일을 요청한다. **추측으로 파일 내용을 지어내지 않는다.**

### 작업 → 확정의 흐름 (반드시 이 순서)

1. 논의 · 계산 · 실측은 `Docs/작업/<주제>.md`에 적는다(지저분해도 된다)

## 2. 절대 규칙

- ⛔ **규칙서는 깨끗하게 유지한다.** 누가 와서 읽든 읽기 깔끔한 **확정 규칙만**. 날짜 · 이력 · 실측 · 후보 · 「검토 중」 · ⚠ 경고문을 넣지 않는다. **확정 안 된 칸은 「(미정)」 한 단어로만** 표시한다(값이 적혀 있으면 그건 임시값이라는 뜻)
- ⛔ **임시값을 정본에 박지 않는다.** 미정 수치는 0 자리표시자 · 파라미터로 빼고 「(미정)」으로 적는다
- ⛔ **폐기 표시는 그 문장 자리에 박는다.** 절 아래 주석으로 끝내면 몇 달 뒤 그 문장이 근거로 인용된다. 상호 참조는 행 번호가 아니라 **절 제목**으로
- ⛔ **커밋 · 푸시는 사용자가 요청할 때만.** 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다
- **구조는 사용자가 정한다.** 너는 주어진 구조 안에서 수치를 계산 · 판단하고, 구조가 문제로 보이면 **사실만 보고**한다(임의로 바꾸지 않는다)
- **스킬 밸런싱은 스킬 간 상대 비교 + 유틸로만.** ⛔ 절대 승률 · 골드 환산으로 스킬 값을 정하지 않는다
- 정본 관계 — VBA `.bas` + `simskill_data.ps1`이 스킬 · 규칙의 정본이고 **sim_py는 실행기**다. 엔진 로직을 네 판단으로 바꾸지 마라

## 3. 측정 방법론 — 비싸게 배운 것들

**이걸 안 지키면 숫자가 통째로 무효가 된다. 실제로 오늘만 두 번 버렸다.**

### 틀

- **스킬 성능은 「1장 교체」로 잰다.** 같은 카드로 3칸을 채우면 빛 드는 카드 · BLUE 카드가 틀 때문에 0으로 나온다. **0.000이나 똑같은 수치가 여러 줄 보이면 값이 아니라 틀을 먼저 의심해라**
- **도사림은 「전투당 1회」로 잰다.** 매 턴으로 재면 전 카드가 무너진다(피의 서약 매턴 −43.7 대 1회 −0.1)
- **조건부 카드는 조건 정책 + 폴백으로 잰다** — 조건이 거짓일 때 슬롯을 비우지 말고 **기준 카드로 교체**해라. 「안 쓰는 턴」을 행동 손실로 벌주면 안 된다. 정화 A가 강제 매턴 −31.0pp → 조건부 −2.5pp로 바뀐 게 이 효과다(사용/판 6.09 → 0.55)
- **버리는 칸을 만들어라** — 평타 3칸 중 하나를 중립 필러로 고정하고 **그 칸만** 교체한다. 그래야 기준선의 엔진 카드가 안 빠진다
- **잡몹 열의 결투 수치는 「효과가 꺼진 몸체 값」**이다(잡몹은 결투를 안 낸다). 효과는 보스 열, 몸체는 잡몹 열에서 읽는다

### 읽기

- **노이즈 실측 = 표준편차 0.64pp → 2pp 이하 차이는 읽지 않는다.** 새 기준선을 쓸 때마다 시드 3벌로 다시 재라
- **Δpp를 그대로 줄 세우지 마라** — 조건 충족률이 카드마다 달라서, `Δpp`(총 기여)와 `Δpp ÷ 사용/판`(사용당 값)을 **둘 다** 봐야 한다
- **바닥 포화를 구분해라** — Δpp가 여러 줄 같은 값에 몰리면 승률 0%에 붙은 것이다. 그게 **틀 아티팩트**인지 **진짜 값**인지는 **만개/판 같은 보조 지표가 같이 단조롭게 움직이는지**로 판별한다
- ⚠ **만개/판은 승률의 대리 지표가 아니다** — 만개가 제일 많은 기준선이 승률은 제일 낮았다. 기준선은 **승률 30~60% 대역**으로 고른다
- **시너지 `S(A,B) = AB − A − B + 0`은 승률로 읽지 마라.** 측정 4개의 합차라 sd(S) ≈ 1.3pp이고 승률은 판당 0/1이라 분산이 최대다. **「같은 시드」도 페어링을 못 만든다**(카드가 다르면 난수 소비 개수가 달라 1턴 만에 어긋난다)
  → **연속 지표(첫 만개 도달 턴 · 뼈 순변화 · 받은 피해)로 후보를 훑고, 남은 2~3쌍만 판 수를 4배로 올려 승률로 확인.** sd(S)는 시드 3벌로 직접 재라
- ⚠ `첫 만개 도달 턴`은 **도달한 판만** 평균한다 — `만개 도달 판 비율`과 같이 읽어라(생존편향)

### 조건문 규약 (B안, 사용자 확정)

조건을 붙이면 **거의 모든 카드가 좋아진다**(안 좋을 때 안 내니까). 카드마다 자유롭게 최적화하면 전부 같은 값으로 수렴해 비교가 무너진다. 그래서 조건은 **카드 규칙으로 승격하지 않고 측정 정책으로만** 두되:

1. 절은 **2개 이하 · AND만**. OR · 중첩 금지
2. **그 카드가 실제로 쓰거나 만드는 자원만** 참조한다
3. 미래를 보지 않는다(현재 상태만)
4. **같은 종류 카드는 같은 조건 틀**을 쓴다. 카드마다 따로 튜닝해 값을 올리지 않는다
5. **폴백은 그 틀의 기준 카드 하나로 고정**한다

**기록** — 측정 표에 `조건문 · 조건 충족률 · 사용/판`을 항상 같이 적는다. **규칙서엔 값만**, 조건문은 **개발로그 · 작업 노트**에 남긴다.

| 실패 | 횟수 | 교훈 |

## 4. 현재 상태

### 끝난 것

- **측정 프레임 v2** — 조건부 사용 정책(`policy.py`) · 시너지 러너(`synergy.py`) · 보조 지표(첫 만개 도달 턴 · 뼈 흐름 · 가불 흐름). 정책을 안 주면 기존 동작과 동일(hasattr 가드)
- **엔진이 정본 18.7을 따라잡음** — 은신 재구현(행동 단위 · 덮어쓰기 · 페이오프가 부위 선택) · 낙일 표식 발화(확정 체력 피해) · 유진 3카드(시한 전염 · 소문 · 숨통)
- **히후미 구조 11건 확정 + 정본 반영** — 가불 · 침체 · 몸에 새기다 두 축 · 결투 J/K/L/M · 위세 2형 배당 · 대실패 공통 규칙 · 완전 차단 정의
- **유진 · 올라프 성장 스킬 구조 확정 + 정본 반영**(18.8 / 17.6)

### ⛔ 막혀 있는 것 — 이게 다음 작업이다

**1순위 · 스킬 풀 최종 채택** — 지금 풀이 목표치를 한참 넘겼다(히후미 평타 10+ · 결투 13 · 도사림 10 / 올라프 평타 16 · 결투 21 · 도사림 9 / 유진 결투 16). **채택 안 될 카드를 측정하는 건 순수 낭비**고, 성장 스킬 4축(유진 집행·판단 / 올라프 침잠·통제)이 **분류(평타/결투) · 빛 · 굴림 수 미정**이라 구현조차 못 하고 있다.

**2순위 · 히후미 스킬 색(RED / BLUE) 전부 미배정** — BLUE는 체력 피해가 0이고 흐트러짐만 깎는다. **색 하나로 카드 값이 통째로 바뀐다.** 지금까지 잰 히후미 수치는 전부 RED 가정 위의 값이다.

**구조 결정 대기 (사용자 몫)**
- ⚠⚠⚠ **만개 의존** — 보스전에서 골단 만개 없이는 사실상 0%다(골단만 빼면 승률 0.705 → 0.0003). 측정 틀을 두 번 고쳤는데 두 번 다 같은 벽에 부딪혔다. 이대로 둘지 / 두 번째 경로를 만들지 / 만개 크기를 줄일지
- ⚠⚠⚠ **보호 ↔ 뼈 모순** — 규칙서 11.2가 히후미 대표 크기형을 「보호 · 열기」로 배정했는데, **보호 = 받는 피해 −N = 뼈 수입 −N**이라 자해다. 뼈를 한 톨도 안 쓰는 카드가 보호를 준다는 이유만으로 만개 0.750 → 0.147로 무너졌다
- **빚지기 ↔ 골단 자원 경합** · **올라프 자기 출혈 3장**(−50.4 / −37.0 / −25.4pp, 값으로 못 고침) · **히후미 B07 정화 A**(가불 조건이 안 걸려 값이 안 움직임) · **히후미 도사림 5장이 수치로 구분 안 됨**(폭 3.9pp, 노이즈 ±2pp) · **B03 · B09 보스 특화 편향 수용 여부** · **올라프 광기 소비처**(보류) · **VBA ↔ sim_py 드리프트**

### ⏭ 다시 재야 하는 것

- **조건부 카드 — 전 캐릭터 무효.** v2 폴백 틀 이전 값은 전부 「매 턴 강제」로 잰 값이다. **올라프도 해당**(굳히기 · 피의 대가 · 피의 맹세 · 전부 되갚다 · 물고 늘어지기 등)
- **무조건 카드는 대체로 유효** — 정책을 안 주면 엔진이 동일하다
- **유진 전체** — 09-17 값이라 상한 폐지 · 고통 확장 이전이고, 낙일 표식 발화까지 바뀌었다
- **히후미 대부분** — 색 미배정 + 구조 재설계
- ⏭ **미착수 작업: 재측정 대장** — 카드별로 언제 · 어떤 틀 · 어떤 엔진에서 잰 값인지 적고, 조건부/무조건을 갈라 무효 표시를 **그 문장 자리에** 다는 것. 올라프부터 하면 건질 게 제일 많다

윈도우에 실제 Python 3.14.6이 설치돼 있지만 시스템 환경에는 `openpyxl`이 아직 없다. `sim_py`는 xlsm을 읽으므로 시스템 Python으로 돌리려면 `pip install openpyxl`이 필요하다. 2026-09-24 검증은 Codex 번들 Python 3.12 + `openpyxl 3.1.5`로 `validate_measurement_v2.py`와 `validate_engine_follow_18_7.py`를 직접 실행해 통과했다.

`Docs/스테이지 맵 기획_계산기.xlsm`은 VBA · 도형 · 버튼을 포함한다. openpyxl로 저장하지 말고, VBA 수정은 Excel COM 경로에서만 한다. 일반 측정은 `sim_py`가 xlsm을 읽기만 하며 최신 미이식 스킬은 `sim_py/data/extra_skills.txt` 오버레이로 받는다.

### 번들 굽는 법

sim_py가 바뀌면 사용자가 `abyss-workspace\tools\make_gpt_bundle.ps1`을 한 번 돌린다. 현재 sim_py + 현재 Docs xlsm + README를 바탕화면에 zip으로 굽고, **넣은 xlsm의 수정 시각까지 찍어준다**(낡은 걸 구웠는지 보이라고).

⚠ 번들의 `sim.xlsm`은 09-21자다. 맥에서 xlsm을 다시 저장할 수 없어서(openpyxl 재저장 시 도형 · 버튼이 날아간 사고가 있었다) 그 뒤 작업분은 **`sim_py/data/extra_skills.txt` 오버레이**에 들어 있고, 그 오버레이는 번들에 포함된다.
