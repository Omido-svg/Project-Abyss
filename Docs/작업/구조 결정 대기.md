# 구조 결정 대기 — 사용자 · 쳇

**진짜 구조 문제 · 아직 규칙 자체가 정해지지 않은 항목만 둔다.** 결정이 나면 ① 규칙서 해당 문장을 고치고 「(미정)」을 뗀다 ② 요약본 · 명세 · `sim_py/data`를 맞춘다 ③ 개발로그 ④ **이 파일에서 그 항목을 지운다**(✅로 남겨 두지 않는다).

**구조 미결로 보는 것** — 규칙끼리 충돌한다 · 처리 시점을 정할 수 없다 · 대상 / 처리 순서 / 발동 조건이 안 정해졌다 · 효과가 구조상 절대 발동할 수 없다
**구조 미결이 아닌 것** — 구조는 정상인데 밸런스가 나쁘다 · 수치가 아직 없다(→ 아래 수치 TODO) · 특정 카드 사용률이 낮다 · 특정 무기만 잘 / 못 쓴다 · 시뮬 승률 편차 · 특정 잡몹 조합이 쉽거나 어렵다

> 지금까지의 결정(10-01 ~ 10-27 (4))은 규칙서 · 엔진에 반영하고 이 파일에서 지웠다 — 개발로그 참조. 이전 측정 · 밸런스 보고는 캐릭터별 작업 노트(`유진.md` · `올라프.md` · `히후미.md` · `잡몹.md` · `공통 규칙.md`)의 「이전 측정 · 밸런스 보고」 절로 옮겼다(이력).

## 🧭 밸런스 원칙 (10-27 사용자)

- 세부 밸런스는 **실제 플레이테스트 뒤** 조정한다. 측정값은 참고자료이지 구조 변경의 자동 근거가 아니다
- 카드 · 무기별 사용률 편향을 허용한다. 모든 선택지를 비슷한 승률 · 가치로 맞추는 것을 목표로 하지 않는다(±5pp 대역 맞추기 폐기)
- 지금 조정하는 것은 **터무니없이 강하거나 약해서 구조 자체를 망가뜨리는 경우**뿐이다
- 10-09 방향(잡몹전 격차는 빌야르 · 천명 낙일을 올려서 맞추고 히후미는 낮추지 않는다)은 유지 — 근거 수치 `잡몹.md`

## 🔧 구조 미결

- **체력 상점 가치 부족 (11-24 사용자 — 기획에서 정할 것)** — 헌혈(체력을 내주고 얻는) 시스템 자체는 마음에 든다. 그러나 지금 체력 상점이 하는 일은 **최대체력 +1 = 현재체력 3** 하나뿐이다(현재체력 → 골드 환율은 (미정)이라 꺼져 있다). 골드 상점이 아이템 매대 + 증강 상점(11-24 신설, 별도 페이지)을 갖는 것에 비해 가치가 떨어진다
  - 사용자가 낸 방향 둘 — ① **체력으로 아이템을 살 수 있게 한다**(상점인 만큼) ② **골드 상점에 없는 상품을 체력 상점에 둔다**
  - 걸린 것 — 체력 → 골드 환율(2.5 임시)이 정해지지 않았다 · 체력 회복 증강(일회성)과 체력 → 골드 교환이 맞물려 차익 거래가 되지 않는지(증강 상점은 상시 증강만 판매하도록 해서 이 문제는 피했다 — 11-24)
  - 구현은 기획 결정 뒤. 하네스(`Run Flow Test`)의 체력 상점은 그대로 둔다

- 나머지 「(미정)」은 수치 · 카드 풀 확충 · 시작 지급 카드 · 아이템 · 내성 배정 · 굴림 타입 · 엘리트 / 보스 콘텐츠 · 적 스킬 · 명명이다 — 구조 미결이 아니다.

**다음 작업 축 = 1층 전체 확인** — 1층 보스 이단 심문관(규칙서 12.5) · 1층 엘리트 2종(12.6)을 엔진에 구현하고 1층 전체 전투 기준으로 밸런스를 본 뒤 다음 스테이지로 간다(시뮬 구현은 11-03 완료). **1층 밸런스 · 승률은 1층까지 만들어 직접 플레이하며 판단한다(11-03 사용자)** — 시뮬 승률은 참고용, 별도 측정을 걸지 않는다. **남은 1층 일 — 명세 엑셀 재생성(윈도우) · 명명 → 1층 플레이테스트.** 엔진 · 명세 데이터는 11-04 반영 남은 엘리트 4종 · 중간보스 2종 · 메인보스 1종은 그다음(규칙서 12.7)
